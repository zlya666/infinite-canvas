# 自建后端接口文档

本文面向后端开发。当前仓库是 **Vite + React 纯前端**：画布 JSON、图片/视频/音频 Blob、「我的素材」、生成历史都在浏览器 IndexedDB（localforage，库名 `infinite-canvas`）。AI 生图/生视频由浏览器直连火山方舟等渠道，**不经过本仓库后端**。

产品目标：

1. **去掉右侧 Agent**（本地 Codex 面板），不作为产品功能。
2. **上传与读取资源一律走接口**，浏览器只做短期缓存（object URL），不以 IndexedDB 为权威存储。
3. 前端继续跟 **上游 `main`** 合入新功能；定制尽量用适配层和开关，不要大面积删上游文件。

建议 Base URL：`https://{api-host}/api/v1`  
鉴权：`Authorization: Bearer {access_token}`  
统一 JSON：`Content-Type: application/json`  
时间一律 ISO-8601 UTC（如 `2026-08-14T03:00:00.000Z`）  
用户数据必须按 `user_id` 隔离，禁止跨用户读写。

## 当前前端数据落点（对接时必须覆盖）

| 能力 | 现状 | 应对接口 |
|------|------|----------|
| 登录 | 可选 Supabase 邮箱登录 | `POST /auth/login` 等 |
| 画布项目 JSON | IndexedDB `app_state` + 可选 Supabase `projects` | `/projects` |
| 图片 Blob | IndexedDB `image_files`，key 形如 `image:{nanoid}` | `/media` |
| 视频/音频 Blob | IndexedDB `media_files`，key 形如 `video:` / `audio:` | `/media` |
| 我的素材 | IndexedDB `app_state` 里的 asset 列表 | `/assets` |
| 生图/生视频历史 | `image_generation_logs` / `video_generation_logs` | `/generation-logs`（可二期） |
| AI 渠道 Key、模型 | 浏览器本地 config store | **仍放前端**，不要写入业务库 |
| 提示词中心 | 拉第三方 JSON + 本地缓存 | 可继续前端直连，非必须 |
| 右侧 Agent | 连本机 Canvas Agent / Codex | **产品关闭**，后端无需实现 |

画布 JSON 里节点 `metadata.content` 现在经常是会话级 `blob:` URL。持久化时 **只存 `storageKey`（即媒体 id）**，展示时用接口返回的 `url` 临时填回 `content`。

## 约定

### 统一响应

成功：

```json
{ "ok": true, "data": {} }
```

列表：

```json
{
  "ok": true,
  "data": { "items": [], "total": 0, "page": 1, "pageSize": 20 }
}
```

失败：

```json
{
  "ok": false,
  "error": { "code": "UNAUTHORIZED", "message": "未登录或登录已过期" }
}
```

常用 `code`：`UNAUTHORIZED`、`FORBIDDEN`、`NOT_FOUND`、`VALIDATION_ERROR`、`PAYLOAD_TOO_LARGE`、`UNSUPPORTED_MEDIA_TYPE`、`CONFLICT`、`INTERNAL`。

### 分页

`page` 从 1 开始，`pageSize` 默认 20，最大 100。

### 媒体 id（对应前端 `storageKey`）

上传成功后返回的 `id` 必须能直接当作前端 `storageKey`。建议格式：

- 图片 `image_{uuid}`
- 视频 `video_{uuid}`
- 音频 `audio_{uuid}`

`url` 为可 GET 的 HTTPS 地址（对象存储签名 URL 即可）。建议有效期 1–24 小时；过期后前端再调 `GET /media/{id}` 换新 URL。JSON 业务数据里 **禁止** 存 `blob:`、data URL。

体积建议：图片 ≤ 30MB，视频 ≤ 200MB，音频 ≤ 15MB（与当前 Seedance 参考限制对齐）。

## 1. 认证

### `POST /auth/register`

```json
{ "email": "user@example.com", "password": "******", "displayName": "张三" }
```

返回 `User` + `tokens`。

### `POST /auth/login`

```json
{ "email": "user@example.com", "password": "******" }
```

### `POST /auth/refresh`

```json
{ "refreshToken": "..." }
```

### `POST /auth/logout`

使当前 refresh token 失效。

### `GET /auth/me`

返回当前用户。

`User`：

```ts
{
  id: string;
  email: string;
  displayName: string;
  avatarUrl?: string;
  createdAt: string;
}
```

`tokens`：

```ts
{
  accessToken: string;   // 建议 2h
  refreshToken: string;  // 建议 30d
  expiresIn: number;     // access 秒数
}
```

## 2. 媒体（优先实现）

所有用户上传、画布节点、参考图/参考视频/参考音频、素材封面、生成结果，都走这里。

### `POST /media`

`multipart/form-data`

| 字段 | 说明 |
|------|------|
| `file` | 必填，二进制 |
| `kind` | 必填：`image` \| `video` \| `audio` |
| `filename` | 可选 |

返回：

```ts
{
  id: string;          // 即 storageKey
  kind: "image" | "video" | "audio";
  url: string;         // 签名或公开可读 URL
  mimeType: string;
  bytes: number;
  filename?: string;
  width?: number;      // 图/视频
  height?: number;
  durationMs?: number; // 视频/音频
  createdAt: string;
}
```

前端现状对照：`uploadImage()` / `uploadMediaFile()` 现在把 Blob 写入 IndexedDB 并 `URL.createObjectURL`。对接后这两个函数改为调本接口，再用返回的 `url` 显示。

### `GET /media/{id}`

返回同一条媒体对象（刷新签名 URL）。无权限或未找到 → `404`/`403`，不要泄露他人资源。

### `GET /media/{id}/file`

可选：`302` 到对象存储，或直接流式输出文件。用于 `<img>` / `<video>` / 下载。

### `DELETE /media/{id}`

删除对象。若仍被画布节点或素材引用，返回 `409 CONFLICT`（推荐），或允许删除由前端自行保证引用完整性。

### `POST /media/batch`

```json
{ "ids": ["image_xxx", "video_yyy"] }
```

返回 `items: Media[]`，用于打开画布时一次性把节点上的 `storageKey` 换成可播放 `url`。

## 3. 画布项目

前端类型：`CanvasProject`（`web/src/stores/canvas/use-canvas-store.ts`）。

```ts
type CanvasProject = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[]; // Agent 关闭后可存空数组
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
};
```

节点：

```ts
type CanvasNodeData = {
  id: string;
  type: "image" | "text" | "config" | "video" | "audio" | "group" | string;
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: Record<string, unknown>;
};

type CanvasConnection = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
};
```

`metadata` 常见字段（后端当 JSON 原样存，不要裁剪未知字段，插件节点会加字段）：

- 通用：`content`、`prompt`、`status`（`idle|success|loading|error`）、`errorDetails`、`model`、`storageKey`、`mimeType`、`bytes`
- 图片：`size`、`quality`、`count`、`images[]`、`primaryImageId`、`naturalWidth`、`naturalHeight`、`references[]`（里面是媒体 id）
- 视频：`seconds`、`vquality`、`size`（比例）、`generateAudio`、`watermark`、`durationMs`
- 文本：`fontSize`、`reasoningEffort`

**入库规则：** `content` 若是 `blob:` 应丢弃或置空，只保留 `storageKey`。多图节点 `images[].content` 同样处理。

### `GET /projects`

Query：`page`、`pageSize`。  
列表项可只含 `id, title, createdAt, updatedAt`（缩略图二期再加）。

### `GET /projects/{id}`

返回完整 `CanvasProject`。

### `PUT /projects/{id}`

幂等保存。Body 为完整项目 JSON（可与 `CanvasProject` 一致）。

用 `updatedAt` 做乐观锁：若库中记录比请求更新，返回 `409`，body 带服务端最新项目，避免多标签互相覆盖。

新建：前端已用 `nanoid` 生成 `id`，后端按 id upsert。

### `PATCH /projects/{id}`

可选。只改 `title`。

### `DELETE /projects/{id}`

删除项目。节点引用的媒体 **不要级联删**（可能还在素材库或其它画布）。

### `POST /projects/{id}/duplicate`

可选。复制项目，节点里的 `storageKey` 继续指向同一媒体（引用而非复制文件）。

保存频率：前端对画布有约 400ms～800ms 防抖。接口需能扛频繁 PUT，建议按 `user_id + id` 整行覆盖 JSON。

## 4. 我的素材

前端类型：`web/src/stores/use-asset-store.ts`。当前只有 `text | image | video`（音频素材可按同样结构预留）。

```ts
type Asset = {
  id: string;
  kind: "text" | "image" | "video" | "audio";
  title: string;
  coverUrl: string;     // 持久化请改存 coverMediaId
  coverMediaId?: string;
  tags: string[];
  source?: string;
  note?: string;
  createdAt: string;
  updatedAt: string;
  metadata?: Record<string, unknown>;
  data:
    | { content: string } // text
    | { storageKey: string; width: number; height: number; bytes: number; mimeType: string }
    | { storageKey: string; width: number; height: number; bytes: number; mimeType: string; durationMs?: number };
};
```

读列表时把 `storageKey` 解析成临时 `url` 填到前端现有的 `data.dataUrl` / `data.url` / `coverUrl`。

### `GET /assets`

Query：`kind`、`q`（标题搜索）、`page`、`pageSize`。

### `POST /assets`

创建。图片/视频必须先 `POST /media`，再把 `id` 写入 `data.storageKey`。

### `PATCH /assets/{id}`

改标题、标签、备注等。

### `DELETE /assets/{id}`

只删素材记录，默认不删媒体文件。

## 5. 生成历史（二期）

工作台 `/image`、`/video` 现在把每次生成写入 IndexedDB。

生图记录要点：`id, createdAt, title, prompt, model, config, references[], images[]`（每张图带 `storageKey`）。  
生视频记录要点：`id, createdAt, title, prompt, model, config, references, videoReferences, audioReferences, video.storageKey, task, status, error`。

### `GET /generation-logs`

Query：`type=image|video`、`page`、`pageSize`。

### `PUT /generation-logs/{id}`

### `DELETE /generation-logs/{id}`

### `POST /generation-logs/batch-delete`

```json
{ "ids": ["..."] }
```

## 6. 明确不做

| 项 | 原因 |
|----|------|
| 右侧 Agent / Codex / Skill | 产品关闭；本机进程，不是你们的 HTTP 服务 |
| 代发火山方舟 / OpenAI | 继续浏览器直连；API Key 留在用户浏览器 |
| WebDAV 同步 | 被本套接口替代 |
| 提示词仓库镜像 | 现有前端已拉公开 JSON |

## 推荐实现顺序

1. 认证 + `POST/GET /media` + `GET /media/batch`
2. 画布 `GET/PUT/DELETE /projects`
3. 素材 `CRUD /assets`
4. 生成历史
5. 前端把 `image-storage.ts` / `file-storage.ts` / `use-canvas-store` / `use-asset-store` 改成调上述接口（IndexedDB 仅作可选离线缓存）

对象存储（OSS/S3/MinIO）只给后端；前端只拿短时 URL，避免把存储密钥放进前端。

## 跟上游 `main` 合代码（给前端同学）

本仓库会继续从 Infinite Canvas 上游 `main` 合并新功能。约定：

1. 产品分支（如 `product`）定期 `git merge` 上游 `main`。
2. 右侧 Agent 已从本产品移除；合入上游时若又带回 Agent UI，继续删掉入口，不要恢复面板。
3. 媒体改造集中在 `web/src/services/image-storage.ts`、`file-storage.ts` 和少量 store，不要把 IndexedDB 调用散落到页面里新写一套。
4. 合入后若上游改了 `CanvasProject` / `CanvasNodeMetadata` 字段，后端 JSON 原样存储即可，无需立刻改表结构。
